# 保存構造と処理契約

## Workspace

ソース実行・editableインストールのデフォルトはプロジェクト内の `BaseTraj_Workspace/` です。起動ディレクトリに依存しません。
ソースを持たないwheelインストールではユーザーホームの `MiniTopol/BaseTraj_Workspace/` を使用します。
Python APIの引数、CLIの `--workspace`、環境変数 `MINITOPOL_WORKSPACE` の順で指定を優先します。
ディレクトリとDBは初回利用時に作成し、既存データを初期化し直しません。

| パス | 内容 |
|---|---|
| `trajectories/<id>/A.zarr` | Zarr v3、原座標 `positions[frame, point, xyz]` (float32、Å)、`time[frame]` (float64、ps)、`box[frame, vector, xyz]` (float32、Å) |
| `trajectories/<id>/atoms.parquet` | Aの点順序、元の原子番号（0起点）、原子名・元素・残基・セグメント |
| `trajectories/<id>/annotations.parquet` | 明示的な鎖・連続区間、原子役割・質量・半径の任意上書き。化学結合テーブルは含めない |
| `trajectories/<id>/manifest.json` | 入力ハッシュ、選択条件、フレーム数、コミット済み境界、完了状態、単位 |
| `trajectories/<id>/bonds.parquet` | 追加の静的結合表現。Aの原子番号 `point_i < point_j` の無向エッジ。0本も許可 |
| `trajectories/<id>/bonds.json` | 結合表現単独の出典・ハッシュ・完了記録 |
| `descriptors/<name>/<trajectory>/<representation>/<result-id>.parquet` | 検証後の結果と定義メタデータ |
| 同名 `.json` | Parquetの完了記録。DB登録前に停止した場合の復旧元 |
| `descriptors/<name>/<trajectory>/A/<result-id>/part-*.parquet` | 10記述子の分割出力。全パート完成後に正式登録 |
| `analyses/<id>.json` | 記述子ごとの実行結果、失敗理由、定義ID・結果ID・行数・未定義値数 |
| `work/<job-key>/` | 中断再開用の位置合わせ座標・集計・FFT中間量。原データは変更しない |
| `integrated.duckdb` | 完了した軌跡、Cの変換規則、結果の定義・範囲・相対パス、独立した結合表現の管理情報。結果数値は複製しない |
| `locks/` | プロセス間ロック。残存ファイル自体はロック保持を意味しない |

変換規則の正本はDuckDB内の `representations` 表です。
入力GRO・XTCはコピーしません。軌跡の登録後、通常の読み出しはAと原子表から行います。

## 入力と科学的な意味

GROには元素・溶媒種・結合の完全な定義がありません。溶媒の残基名は呼び出し時に明示します。
元素は元入力の全原子分を明示指定できます。省略時はMDAnalysisによる原子名からの推定であることをmanifestに保存します。
イオンや非標準原子名など、推定が曖昧な入力では明示指定を使います。H/D/Tと指定された溶媒の全原子をAから除外します。
原子順序と全フレームの時刻を維持し、一律の並進・回転除去は行いません。ボックスがないフレームはNaNを保存します。

Registryは用途に応じて最小像距離とNoJump座標の取得を提供します。保存するAは原座標です。前提条件は [Calculatorの文書](calculators.md) に記載しています。
TPRに由来する静的な共有結合の接続グラフは、Aとは独立した結合表現として登録できます。原子間距離・PDBによる結合推定、水素結合、内部幾何は対象外です。

## Cの登録

初期登録はAのみです。`Registry.register` はCの定義を登録するだけで、全軌跡の生成や記述子計算を開始しません。
現実装では、対象軌跡Aの0起点原子番号のグループと重みを明示指定する変換を提供します。
この変換を一般的な質量中心などと見なす暗黙の規約はありません。登録時のTopology指紋と一致する軌跡だけで使用できます。
読み出しの際、対象チャンクから重み付き座標を生成し、Cの座標は保存しません。
原子がPBCで分断されている場合にこの重み付き座標をそのまま物理的な重心と解釈することはできません。
今回のPBC付きCalculatorはAのみを対象とします。既存のCの重み付き変換にはPBC補正を暗黙に追加しません。定義は不変とし、変更時は別IDで登録します。

## 再開・競合・メモリ

変換は時間方向のZarrチャンク境界でコミットします。書き込み途中でプロセスが停止した場合、再実行は未コミットのチャンクを上書きします。
異なる入力や変換条件を同じIDへ登録するとエラーになります。元入力のSHA-256照合にはXTC全体の逐次読み取りが必要です。
同じ軌跡の変換は専用ロック、カタログ接続は共通ロックで直列化します。アプリ外からのDuckDB書き込みはこの制御の対象外です。
変換中は元入力を変更しないでください。

自動チャンクは座標ペイロード約32 MiBを目安に原子数で調整し、1～1024フレームです。これはプロセス全体のメモリ上限ではありません。
MDAnalysis・Zarr・圧縮・C変換の作業領域が加わり、単一フレームより小さくは分割しません。
`chunk_frames` を指定して調整できます。Registryは既定で保存時のチャンク長を使います。
`query_results` は検索結果をArrow表としてメモリに返すため、大量結果には対象・列・フレーム範囲を指定します。

Parquetは一時ファイルへ出力・行数検証してから置換し、完了記録を保存した後にDBへ登録します。
同一の定義・軌跡・区間に異なる値を再登録するとエラーになります。重複登録は冪等です。
同じ定義の重複区間は拒否します。中断後は `recover` で完了記録からカタログ登録を復旧できます。
新しい完了記録はParquetファイルのSHA-256を保持し、復旧・計算済み区間のスキップ前に照合します。
旧形式は元のペイロードハッシュと照合し、行数だけで正常扱いしません。旧形式で元の独自スキーマメタデータが失われた場合など、照合できないデータはエラーとして報告し、無断で削除・上書きしません。
結果ファイルや完了記録が欠損した場合も、計算済みとして成功を返さずエラーとします。
ストレージ故障・電源断に対する完全な耐久性や、Zarr全チャンクの破損検知は保証していません。

## 記述子

定義、Calculator、結果管理を別モジュールにしています。
`calculate_frames` はフレームごとの独立した計算用で、完了区間を再計算せず再開します。
RMSF・時間相関などの区間集計は、`analyze` が呼び出すそれぞれのCalculatorで処理します。
結果表の必須列は `value` です。フレーム別では整数の `frame` を持ち、区間集計では対象区間や遅れを固有列として定義します。
識別情報と定義は保存時に付加します。Aの10種類は承認済み定義A-1を実装しています。
追加した `descriptor_definitions` 表は計算前の定義登録、`result_parts` 表は分割Parquetの所在を管理します。
既存の単一Parquetと結果表は維持します。分割結果ではresults.pathは完了記録と対応する論理プレフィックスで、実Parquetの所在はresult_parts.pathです。
結果本体の数値をDuckDBへ複製しません。分割結果の親と全パートは同じトランザクションで正式登録します。

### 保存形式と途中状態の互換性

座標のPCodec圧縮とParquetの列別符号化は可逆です。座標・時刻・ボックスの値、Parquetの列・単位・null/reasonの意味は維持します。圧縮方式によってファイル自体のSHA-256は異なります。既存の完成データを自動的に再圧縮・置換しません。

完成結果のmanifestはschema 3です。途中状態は新規作成時にprogress v4のチェックサム付き追記journalを使い、完成時に各パートの整合性を確認してから公開します。既存progress v3はv3のまま再開します。v4を認識しない旧版ではv4の途中状態を再開できません。

SASA・主鎖角・二次構造・Contacts・時間相関は`compact-v1`の分割設定を使います。主鎖角は中間精度を示す`float64-v1`も記録します。異なる処理レイアウトの途中結果には追記せずエラーにします。レイアウトが異なる未完了ジョブは、そのジョブを作成した実装・設定で完了させてください。完成済みの旧形式Parquetは引き続き読み出せます。
