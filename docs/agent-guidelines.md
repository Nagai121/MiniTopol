# MiniTopol：開発エージェントの作業規則

この文書は、ルートの [AGENTS.md](../AGENTS.md) から参照する開発規則です。個別の仕様と操作手順は、それぞれの専門文書を正本として扱い、ここには複製しません。

## 作業前

- 対象コード、既存テスト、対応する `docs/`・`definitions/` を確認し、実装と文書の相違があれば確認結果を区別します。
- ユーザーが確定した仕様と、検討案・未決事項を区別します。未決事項を独断で仕様化せず、依頼された範囲を変更しません。
- 新機能を追加するために既存の機能や検証条件を無断で縮小しません。無関係な修正を混ぜません。

## 科学データと既存契約

- 座標・時間・boxの単位、原子とフレームの順序、PBC処理、記述子の定義、疎データやnullの意味論を、根拠なく変更しません。
- 科学的意味論を変更する場合は、対応する定義・検証条件との関係を明示し、比較テストを用意します。
- 原データ・正本・台帳・中断復旧情報を保護し、既存ファイルを不意に上書き・削除しません。配置変更は検証・排他・障害時の復旧を含めて扱います。
- ProviderがWorkspaceの解釈、読み出し、保存階層、共有メモリとLeaseの生存期間を管理します。Readerは接続クライアントとして薄く保ち、内部データ形式を解釈させません。

## 変更と検証

- 変更箇所に対応した回帰テストを追加し、可能な範囲で `python -m pytest -q` とGitHub Actionsの結果を確認します。
- データ破損、正本の喪失、競合、中断復旧、読み出し互換性に関わる変更では、正常系だけでなく失敗・再試行時の動作も検証します。
- 未実行の環境・未測定の性能を「検証済み」と報告しません。性能値には実際に使用した入力・測定条件を付記します。
- mainへの反映、PR作成や統合などのリポジトリ操作は、ユーザーによる明示的な指示の範囲内で実施します。

## 対象文書の選択

ルートの [AGENTS.md](../AGENTS.md) に作業内容別の参照先があります。技術文書は必要なものを読み、無関係な資料を一律に読み込まないでください。
